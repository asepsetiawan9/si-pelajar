Catatan Pengembangan: Sistem Pelaporan Kinerja Organisasi (SPKO)

Lokasi Penerapan: Pemerintah Kabupaten Garut — Kecamatan Malangbong
Versi Dokumen: Revisi 4.1 (AI-Ready Production Blueprint)
Format Salinan Markdown untuk AI: CATATAN_PENGEMBANGAN_SPKO.md

Ringkasan Arsitektur & Penyelarasan Sistem:
  1. Sistem Internal Kecamatan Malangbong: 100% mandiri untuk satu kecamatan, tidak terhubung ke dinas eksternal. Pengesahan akhir dipegang oleh Camat Malangbong.
  2. Definisi Sekmat: Pejabat struktural Sekretaris Camat sebagai Admin Verifikator dan koordinator pelaporan internal.
  3. Standar Permenpan-RB 53/2014 & 22/2024: Struktur laporan memuat Sasaran Strategis, Rencana Aksi, Capaian Kinerja, Sub-Tabel Rincian Layanan (misal 10 layanan PATEN), serta analisis otomatis Efektivitas & Efisiensi Anggaran.
  4. Sistem Cut-Off: Penguncian otomatis tiap tanggal 10 bulan berikutnya dengan fitur dispensasi dan delegasi input.
  5. Instruksi AI Siap Eksekusi: Setiap fase (Fase 1 s.d 5) dilengkapi blok prompt teknis mandiri untuk dieksekusi oleh AI.

0. Keputusan Desain & Parameter Sistem

Parameter Ketentuan Final Dasar Pertimbangan & Aturan Teknis
Cakupan Sistem Single-Tenant (Internal Kecamatan Malangbong) Aplikasi fokus penuh mengelola pelaporan internal seksi dan sub-bagian di Kecamatan Malangbong tanpa keterlibatan dinas eksternal.
Approver Tertinggi Camat Malangbong Pejabat pembina akuntabilitas kinerja kecamatan (LKj/LKjIP/PKO). Memberikan pengesahan akhir.
Posisi Sekmat Sekretaris Camat (Eselon III/b) Pejabat pembina administrasi, bertindak sebagai Admin Verifikator utama yang meneliti pengajuan seluruh unit sebelum diteruskan ke Camat.
7 Unit Pelapor Wajib Seluruh unit operasional (Leaf Nodes):
  1. Sub Bag Umum, Perencanaan Evaluasi & Pelaporan
  2. Sub Bagian Keuangan dan BMD
  3. Seksi Pemerintahan
  4. Seksi Kesejahteraan Masyarakat
  5. Seksi Pemberdayaan Masyarakat dan Desa (PMD)
  6. Seksi Ketentraman dan Ketertiban (Trantib)
  7. Seksi Pelayanan
 Masing-masing unit wajib menyusun dan melaporkan capaian rencana aksi setiap bulan tanpa ada yang opsional.
Siklus & Batas Waktu (Cut-Off) Tiap tanggal 10 bulan berikutnya (Pukul 23:59 WIB) Contoh: Laporan Agustus 2026 wajib tuntas diinput maksimal 10 September 2026. Lewat batas waktu, form terkunci dan ditandai is_late = true.
Dispensasi & Delegasi Input Dikelola oleh Admin Kecamatan / Sekmat Tersedia fitur buka dispensasi keterlambatan untuk unit tertentu dan input pengganti jika ada pejabat Kasi berhalangan, dengan catatan audit log transparan.
Format Dokumen Output Auto-Generate PDF Resmi Berkop Surat Dokumen cetak PDF ter-generate otomatis persis dokumen fisik Permenpan-RB 53/2014 & 22/2024 berkop Pemkab Garut - Kecamatan Malangbong dan barcode verifikasi Camat.

1. Peran Pengguna & Matriks Hak Akses (RBAC)

Peran (Role) Pejabat Terkait Wewenang & Hak Akses
Superadmin (IT) Pengelola Teknis IT Kelola akun user, role, backup database, audit log, dan parameter teknis sistem.
Admin Kecamatan Sekmat / Tim Evaluasi Kinerja Kelola master sasaran strategis & rencana aksi tahunan, verifikasi/revisi laporan unit, input bantuan (delegasi), buka kunci dispensasi cut-off, dan ajukan laporan kompilasi ke Camat.
Kasi / Kasubag Kepala Seksi / Kepala Sub Bagian Input capaian target vs realisasi, input rincian layanan (misal data 88 pemohon PATEN), realisasi anggaran belanja, unggah bukti dukung, dan ajukan laporan unit.
Camat (Pimpinan) Camat Malangbong Melihat dashboard eksekutif efektivitas & efisiensi belanja se-kecamatan, mengesahkan (Approve) atau mengembalikan laporan kompilasi bulanan.

2. Standar Instrumen Kinerja (Permenpan-RB 53/2014 & 22/2024)

Berdasarkan data dokumen fisik resmi Kecamatan Malangbong, setiap laporan bulanan unit memuat:

  1. Latar Belakang: Dasar hukum Permenpan-RB (template otomatis).
  2. Sasaran Strategis & Rencana Aksi: Terhubung ke Perjanjian Kinerja tahunan Camat.
  3. Realisasi Capaian Kinerja:
    • Target vs Realisasi → Persentase Capaian: (Realisasi / Target) * 100%.
    • Sub-Tabel Rincian Layanan / Kegiatan (Dinamis): Rincian pemohon (misal Seksi Pelayanan: 46 SKTM, 2 Ijin Keramaian, 13 Rekomendasi Kredit, 9 Dispensasi Nikah, 8 Akta Lahir, total 88 pemohon).
    • Catatan keluhan masyarakat, hambatan pelaksanaan, dan solusi.
  4. Analisis Efektivitas Kinerja (Otomatis): 
    Kriteria Efektivitas:
- > 100%       : Sangat Efektif (Istimewa)
- 90% s.d 100% : Efektif (Baik)
- 60% s.d 89%  : Cukup Efektif (Cukup)
- < 60%        : Tidak Efektif (Kurang)
  5. Analisis Efisiensi Anggaran (Otomatis): 
    Kriteria Efisiensi Serapan:
- < 60%        : Sangat Efisien (Istimewa)
- 60% s.d 90%  : Efisien (Baik)
- 91% s.d 100% : Cukup Efisien (Cukup)
- > 100%       : Tidak Efisien (Kurang)
  6. Simpulan & Lembar Pengesahan: Disertai tanda tangan Kasi pengampu dan mengetahui Camat Malangbong.

🚀 FASE 1 — Kerangka Sistem, Otentikasi & 4 Role Pengguna

Tujuan: Kerangka Laravel 11 + Filament v3, Spatie RBAC, dan seeding akun resmi Kecamatan Malangbong.

KONTEKS:
Fase 1 dari 5 — Membangun fondasi sistem "Sistem Pelaporan Kinerja Organisasi (SPKO) Kecamatan Malangbong" menggunakan Laravel 11 dan Filament v3 (Single Application Architecture).

TUJUAN:
Instalasi framework, konfigurasi RBAC Spatie + Filament Shield, migrasi users, dan seeding akun resmi.

LANGKAH EKSEKUSI:
1. Setup project Laravel 11 dengan database MySQL / PostgreSQL.
2. Install Filament v3 Panel: php artisan filament:install --panels.
3. Install package pendukung: spatie/laravel-permission, bezhansalleh/filament-shield, spatie/laravel-activitylog.
4. Jalankan php artisan shield:install.
5. Modifikasi migrasi tabel users dengan kolom:
   - nip (string, nullable)
   - role (enum: 'superadmin', 'admin_kecamatan', 'kasi', 'camat')
   - jabatan (string, nullable)
   - unit_organisasi_id (unsignedBigInteger, nullable)
   - is_active (boolean, default true)
6. Buat UserSeeder dengan data akun resmi Kecamatan Malangbong:
   - Superadmin: superadmin@malangbong.go.id (Role: superadmin)
   - Sekmat / Admin: sekmat@malangbong.go.id (Role: admin_kecamatan, Jabatan: 'Sekretaris Camat')
   - Camat / Pimpinan: camat@malangbong.go.id (Role: camat, Jabatan: 'Plt. Camat Malangbong', NIP: '19700523199303 1 005')
   - Kasi Pelayanan: kasi.pelayanan@malangbong.go.id (Role: kasi, Jabatan: 'Kepala Seksi Pelayanan', NIP: '19801214201410 2 002')
   - Kasi Pemerintahan: kasi.pemerintahan@malangbong.go.id (Role: kasi, Jabatan: 'Kepala Seksi Pemerintahan')
   - Password default: Password123!
7. Buat UserResource di Filament dengan konfigurasi form reaktif: field unit_organisasi_id hanya tampil dan wajib diisi jika role = kasi.
8. Pastikan seluruh akun dapat login ke panel /admin.

🚀 FASE 3 — Formulir Input Kinerja Kasi, Concurrency-Safe Header, & Otomasi Perhitungan

Tujuan: Formulir input capaian terstruktur, sub-tabel dinamis layanan (PATEN), realisasi anggaran, hitung otomatis %, dan atomic header.

KONTEKS:
Fase 3 dari 5 — Membangun formulir input kinerja bulanan untuk Kasi/Kasubag sesuai instrumen Permenpan-RB (Realisasi Kinerja, Sub-tabel Rincian Layanan, dan Realisasi Anggaran).

TUJUAN:
Kasi dapat menginput capaian bulanan secara komprehensif, aman dari race condition, serta sistem menghitung persentase dan predikat efektivitas-efisiensi secara otomatis.

LANGKAH EKSEKUSI:
1. Buat model & migrasi:
   - Laporan (Header bulanan kecamatan, UNIQUE pada bulan_pelaporan).
   - LaporanDetail (Detail per unit, UNIQUE pada [laporan_id, unit_organisasi_id]).
   - LaporanDetailIndikator (Capaian kinerja & belanja per rencana aksi).
   - LaporanDetailLayanan (Rincian pemohon/layanan, misal: 10 item PATEN).
   - LaporanDokumen (Upload file bukti dukung).
2. Buat LaporanDetailResource untuk panel Filament:
   a. Form Wizard / Tabs terstruktur:
      - Tab 1 (Informasi Umum): Bulan Pelaporan, Unit Organisasi (otomatis dari user login), Latar Belakang (pre-filled template), Keterkaitan Rencana Aksi.
      - Tab 2 (Capaian Kinerja & Anggaran): Repeater/Table input berdasarkan Rencana Aksi unit:
        * Input: Target Kinerja, Realisasi Kinerja -> Auto Reactive Hitung persentase_kinerja = (Realisasi / Target) * 100.
        * Auto Predikat Efektivitas: Sangat Efektif (>100%), Efektif (90-100%), Cukup (60-89%), Tidak Efektif (<60%).
        * Input: Pagu Anggaran, Realisasi Belanja -> Auto Reactive Hitung persentase_anggaran = (Realisasi / Pagu) * 100.
        * Auto Predikat Efisiensi: Sangat Efisien (<60%), Efisien (60-90%), Cukup (91-100%), Tidak Efisien (>100%).
      - Tab 3 (Rincian Layanan / Kegiatan): Repeater dinamis (Nama Layanan/Kegiatan, Jumlah Pemohon, Satuan, Keterangan). Sediakan preset cepat untuk Seksi Pelayanan (SKTM, Ijin Keramaian, Rekomendasi Kredit, Waris, Dispensasi Nikah, Akta Lahir).
      - Tab 4 (Evaluasi & Hambatan): Textarea Keluhan Masyarakat, Hambatan, Solusi, dan Simpulan.
      - Tab 5 (Bukti Dukung): Multiple FileUpload (PDF/JPG/PNG, max 10MB per file) disimpan di storage private disk.
3. Concurrency-Safe Auto-Create Header:
   - Saat Kasi menyimpan entri pertama, eksekusi dalam DB::transaction() menggunakan:
     Laporan::firstOrCreate(['bulan_pelaporan' => $bulan->startOfMonth()->toDateString()], ['tahun' => $tahun, 'status' => 'draft']);
4. Validasi Cut-Off Tanggal 10:
   - Jika now()->day > 10 untuk bulan sebelumnya, tolak pembuatan/pengubahan data dan set is_late = true, kecuali ada flag dispensasi aktif dari Admin.
5. Action "Ajukan Laporan Unit":
   - Mengubah status LaporanDetail dari draft/ditolak menjadi diajukan. Form langsung terkunci (read-only). Kirim notifikasi ke Admin Kecamatan.
